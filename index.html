Before you start

Choose your operating system in the bar above; the page then shows only the steps that apply to you. Tick steps off as you go — progress is saved in this browser.

What you'll need

Your Passport York username and password (the same login as York email) with Duo Mobile set up for two‑factor authentication, plus access to the cortex VPN profile and the Michaels-Group share. If you're new to the lab, see Getting access first.

The VPN is always required — on campus too

CortexCache is only reachable through the cortex VPN profile, even from York's wired or wireless network. Without step 1, the mount in step 2 fails or hangs.

1Connect to the VPN

York's VPN client is Ivanti Secure Access, formerly called Pulse Secure — the same product under a new name, so either label may appear on York's pages (and the Linux build still installs to /opt/pulsesecure/). You install it and create the profile once; after that it's a single click to connect.

  1. Installers are on the York UIT Internet Access page, under the VPN tab (Passport York login required to download). Use the version marked Current — 22.8r2 at the time of writing — not the older Pulse Secure 9.1 builds.

    macOS: download the Mac installer, open the package and click through Continue ▸ Install. The client appears in Applications and in the menu bar. If macOS objects to an unidentified developer, allow it under System Settings ▸ Privacy & Security.

    Windows: download the 64‑bit installer (or the ARM64 build on a Snapdragon laptop), run the .msi and accept the defaults. The Ivanti icon appears in the system tray.

    Linux: download the .deb (Ubuntu/Debian) or .rpm (Fedora/RHEL). The client needs a desktop session (it embeds a browser for sign‑in) and two dependencies:

    sudo apt-get install libnss3-tools libwebkit2gtk-4.0-37   # Ubuntu 22.04 / Debian 12
sudo apt install ~/Downloads/ps-pulse-linux-*.deb
sudo /opt/pulsesecure/bin/setup_cef.sh install

    Then launch Ivanti Secure Access Client from your applications menu, or run /opt/pulsesecure/bin/pulseUi. On Fedora/RHEL use sudo dnf install ./ps-pulse-linux-*.rpm instead.

    Ubuntu 24.04 and newer

    The client depends on libwebkit2gtk-4.0-37, which 24.04 no longer ships. The usual workaround is to add the Ubuntu 22.04 ("jammy") repository temporarily, install that one package, then remove the repository. Recent Fedora/RHEL releases have dropped legacy WebKitGTK entirely and may not work until Ivanti updates the client. If you hit this, ask in the lab — a lab machine may be simpler.

  2. Launch Ivanti Secure Access Client (system tray on Windows, menu bar on macOS). In the Connections panel, click +.

  3. TypePolicy Secure (UAC) or Connect Secure (VPN)
    Namecortex
    Server URLhttps://vpngateway.yorku.ca/cortex

    The name is just a label. The server URL must end in /cortex: the generic York VPN profile does not reach CortexCache. Click Save.

  4. Click Connect next to cortex. Enter your Passport York username only (jsmith, not jsmith@yorku.ca) and your password, then Connect.

    Leave “Save settings” unticked

    York InfoSec asks that you don't save your password here: with Duo two‑factor, a saved password causes failed logins later. You'll type it each time you connect.

  5. Your phone receives a Duo Push; tap Approve. The client shows Connected. Leave it connected while you work with the share.

    If no push arrives, open Duo Mobile and tap the Request waiting banner. Or use a passcode instead: type your password, a comma, and the six‑digit code from Duo Mobile in the password field, e.g. mypassword,123456.

2Mount the Michaels-Group share

With the VPN connected, attach the share so it behaves like an ordinary drive or folder. The server and login format are the same everywhere; only the mechanics differ by system.

Servercortexcache-data.nas.sci.yorku.ca
ShareMichaels-Group
Usernameyorku.yorku.ca\your_ppy_id
PasswordYour Passport York password
The domain prefix matters

Put yorku.yorku.ca\ — with a backslash — in front of your Passport York ID, e.g. yorku.yorku.ca\jsmith. Leaving it off is the most common reason a login is rejected.

Choose , or to see the mount steps.

macOS

Finder

  1. In Finder, choose Go ▸ Connect to Server…, or press ⌘ K.

  2. smb://cortexcache-data.nas.sci.yorku.ca/Michaels-Group/

    Click + to save it to your favourites, then Connect.

  3. Choose Registered User. Name: yorku.yorku.ca\your_ppy_id; password: your Passport York password. Ticking Remember this password in my keychain is fine. Click Connect.

  4. It appears under Locations in the Finder sidebar and at /Volumes/Michaels-Group in Terminal. Eject it (⏏ in the sidebar) before disconnecting the VPN or closing your laptop.

Optional: reconnect automatically at login

With the share mounted, open System Settings ▸ General ▸ Login Items & Extensions, click + under Open at Login, and pick the Michaels-Group volume. It reconnects at each login — but only if the VPN is already up, so connect Ivanti first.

Windows 10 / 11

File Explorer

  1. Press Win E, then click This PC in the left pane.

  2. Windows 11: click ⋯ (See more) in the toolbar ▸ Map network drive. Windows 10: it's on the Computer ribbon tab.

  3. \\cortexcache-data.nas.sci.yorku.ca\Michaels-Group

    Tick Reconnect at sign‑in and, importantly, Connect using different credentials — otherwise Windows tries your local account and fails. Click Finish.

  4. User name yorku.yorku.ca\your_ppy_id, password your Passport York password. Tick Remember my credentials so the drive reconnects without asking. The share opens under the drive letter you chose.

Alternative: map the drive from the Command Prompt

In Command Prompt or PowerShell — replace your_ppy_id, and M: with any free letter. You'll be prompted for your password.

net use M: \\cortexcache-data.nas.sci.yorku.ca\Michaels-Group /user:"yorku.yorku.ca\your_ppy_id" /persistent:yes

net use alone lists mapped drives. To disconnect:

net use M: /delete

Linux

CIFS

Written for Ubuntu/Debian. On Fedora use sudo dnf install cifs-utils, on Arch sudo pacman -S cifs-utils; everything else is the same.

  1. sudo apt-get install cifs-utils -y
  2. sudo mkdir -p /mnt/cortex

  3. Replace your_ppy_id with your Passport York ID. The first line reads your password without echoing it, so it never lands in your shell history or in ps output.

    read -s -p "Passport York password: " SMB_PASS; echo
sudo mount -t cifs //cortexcache-data.nas.sci.yorku.ca/Michaels-Group /mnt/cortex \
  -o username=your_ppy_id,password="$SMB_PASS",domain=yorku.yorku.ca,uid=$(id -u),gid=$(id -g)
unset SMB_PASS

    uid=$(id -u),gid=$(id -g) makes the mounted files yours, so you can read and write without sudo.

  4. df -h | grep cortex        # the share and its free space
mount | grep cifs          # all mounted CIFS shares

    Your data is under /mnt/cortex.

  5. sudo umount /mnt/cortex

    Do this before disconnecting the VPN, or processes touching /mnt/cortex may hang.

Optional: a reusable mount script

Save as ~/mount-cortex.sh, run chmod +x ~/mount-cortex.sh, and call it whenever you need the share. It prompts for your password rather than storing it.

#!/usr/bin/env bash
set -e
USER_ID="your_ppy_id"
MP=/mnt/cortex
sudo mkdir -p "$MP"
read -s -p "Passport York password for $USER_ID: " SMB_PASS; echo
sudo mount -t cifs //cortexcache-data.nas.sci.yorku.ca/Michaels-Group "$MP" \
  -o username="$USER_ID",password="$SMB_PASS",domain=yorku.yorku.ca,uid=$(id -u),gid=$(id -g)
unset SMB_PASS
echo "Mounted at $MP"
Don't hard‑code your password

Keep it out of scripts, /etc/fstab and the command line — it's your Passport York password and unlocks far more than this share. For an unattended mount, use a credentials= file with chmod 600, and ask in the lab before setting it up.

Troubleshooting

Most problems come down to one of three things: the VPN isn't connected, the username is missing its domain prefix, or a saved password has gone stale.

The share won't connect, times out, or “server not found”

Nine times out of ten the VPN isn't connected, or is connected to the wrong profile. Open Ivanti and confirm cortex says Connected. The generic York VPN and campus Wi‑Fi do not reach CortexCache. If the VPN is up, disconnect and reconnect it, then mount again.

My username or password is rejected

The username format differs between the two steps. VPN: your_ppy_id alone. Share: yorku.yorku.ca\your_ppy_id, with a backslash, not a forward slash.

On Windows, if you didn't tick Connect using different credentials, Windows may be silently using your local account: disconnect the drive and map it again. If your Passport York password changed recently, update it in Keychain (Mac) or Credential Manager (Windows).

I never get the Duo push

Check your phone has signal or Wi‑Fi and Duo Mobile notifications are on. Open Duo Mobile and look for a Request waiting banner. Failing that, use a passcode: enter yourpassword,123456 in the password field (password, comma, six‑digit code from Duo Mobile). Duo problems such as a new phone are handled by York UIT, not the lab.

Ivanti says my password is invalid even though it's correct

Usually a saved password from an earlier session, which conflicts with Duo. Open the cortex connection's settings in Ivanti, choose Forget saved settings, then connect again without ticking Save settings.

The VPN keeps disconnecting

York's VPN profiles have an idle timeout of roughly 10–30 minutes with no traffic and a hard session limit of 8–10 hours, with a warning a few minutes before. Transfers longer than that get interrupted: split them up, or run them from a lab machine. Laptops going to sleep also drop the VPN and the share with it, so unmount before closing the lid.

Windows: “The network path was not found” (error 53 / 67)

Usually the VPN. Otherwise check for two leading backslashes (\\cortexcache-data…) and no trailing slash. From Command Prompt, ping cortexcache-data.nas.sci.yorku.ca should resolve while the VPN is connected; if it doesn't, the profile is wrong.

Windows: “Multiple connections to a server… are not allowed” (error 1219)

Windows already holds a connection to that server under different credentials. Run net use * /delete to clear all mapped drives, then map the share again.

macOS: “There was a problem connecting to the server”

Check the VPN first. Then make sure the address starts with smb:// and that you chose Registered User, not Guest. If a stale mount lingers, eject anything named Michaels-Group in the Finder sidebar and try again.

Linux: “mount error(13): Permission denied”

Wrong username, password or domain. On Linux the domain is passed separately (domain=yorku.yorku.ca), so username= is your bare Passport York ID without the prefix. Also check you can reach the server: ping -c 2 cortexcache-data.nas.sci.yorku.ca.

Linux: files are read‑only or owned by root

You mounted without uid=/gid=. Unmount and mount again with uid=$(id -u),gid=$(id -g) as shown above. If a different SMB protocol version is needed, add ,vers=3.0 to the options.

Linux: “mount: unknown filesystem type 'cifs'”

cifs-utils isn't installed — go back to step 1 of the Linux instructions.

Transfers are slow or drop out

All traffic goes through the VPN, so throughput depends on your connection and York's gateway. For large datasets, copy in the lab over a wired connection where possible, and don't run analyses directly against the mounted share — copy what you need to local disk, work there, and copy results back.

I can connect but the share is missing or empty

Your Passport York account probably hasn't been added to the share's access group yet. See Getting access.

Getting access

Two permissions are attached to your Passport York ID, and neither is automatic when you join the lab: the cortex VPN profile (everyone at York has the generic VPNYork profile, but restricted profiles are granted per person) and the Michaels-Group share itself. Jonathan requests both for you.

  1. Students and staff normally already do. If Duo isn't set up, follow York UIT's Duo instructions.

  2. Email jmichae@yorku.ca. He submits the VPN profile request to UIT and asks Science IT, who administer CortexCache, to add you to the share's access group. Allow a few working days.

  3. Once you're told access is granted, follow steps 1 and 2 above.

Good citizenship on the share

It's shared storage for the whole lab. Keep your work inside the existing folder structure, don't store personal files there, and never leave your Passport York password in a script or config file on the share.
